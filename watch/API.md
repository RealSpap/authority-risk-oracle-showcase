# Data contract, v1

Everything the dashboard shows from the watch is a file rewritten by the `Watch` GitHub Action every 6 hours (`17 */6 * * *` UTC), committed to the `watch-data` branch of this
repository (the root of the branch is the folder that is called `watch/` in the scripts and in this document) and served raw from
`https://raw.githubusercontent.com/RealSpap/authority-risk-oracle-showcase/watch-data/<file>`. `main` holds the code and the documents written by hand (this one, the README and
the schemas, copied into the branch at every run), so its history is the history of the work. Before the move the same files were committed to `main` under `watch/`; those commits stay,
and the old links answer with a short notice that points here. `status.json` carries `data_location`, the base URL under which every file is served, so a page or a monitor does not need a constant of its own (the notice left on `main` carries it too). No key, no rate limit beyond GitHub's. The on-chain source of truth stays the oracle contracts (`getScore(address)`): these files are a convenience read of them.

Verifying the signature from your own service, without this repository's code (Node 18+, raw Ed25519 key wrapped in SPKI DER; the manifest is canonical JSON: keys sorted, no spaces):

```js
const crypto = require('crypto');
const sig = await (await fetch('https://raw.githubusercontent.com/RealSpap/authority-risk-oracle-showcase/watch-data/signature.json')).json();
const canon = (v) => Array.isArray(v) ? '[' + v.map(canon).join(',') + ']' : (v && typeof v === 'object') ? '{' + Object.keys(v).sort().map(k => JSON.stringify(k) + ':' + canon(v[k])).join(',') + '}' : JSON.stringify(v);
const key = crypto.createPublicKey({ key: Buffer.concat([Buffer.from('302a300506032b6570032100', 'hex'), Buffer.from(sig.public_key, 'hex')]), format: 'der', type: 'spki' });
console.log(sig.signed && crypto.verify(null, Buffer.from(canon(sig.manifest)), key, Buffer.from(sig.signature, 'hex')));   // true: every file listed in sig.manifest.files hashes to what the key signed
```

In Python: `from nacl.signing import VerifyKey; VerifyKey(bytes.fromhex(sig["public_key"])).verify(json.dumps(sig["manifest"], sort_keys=True, separators=(",", ":")).encode(), bytes.fromhex(sig["signature"]))`. Compare `public_key` with the one the README publishes before trusting it.

**What the checks do not prove (written down on 2026-10-11 after a security review).** (1) The signature is checked with the public key written *inside* `signature.json`: a forged manifest signed with a random key still says "valid". It proves the files match what that key signed, not who holds the key; the maintainer's public key is `11baca3ef6a69de4901c185f6cbbd3f93318fbb74f9961a8d39aead841adf409`, pinned in the dashboard (`ARO_PUBKEY`) and written here: compare it with the `public_key` of `signature.json`, and treat a signature made by any other key as invalid. Before 2026-10-11 21:18 UTC the runs were unsigned (`signed: false`), and a run that cannot read the secret says so. (2) `verify_chain.py` checks that every line commits to the previous one; it cannot see that the *end* of the log was cut off. The head of the chain is pinned in the signed manifest (`events_chain_head`), so compare that value, not only "chain intact". (3) An alarm is a line of `events.jsonl` and an issue in the maintainer's private repository, and only when the `ISSUES_TOKEN` secret is set: without it the run prints "alarm raised but no ISSUES_TOKEN" and nobody is told. An oracle that stops answering raises one alarm, then stays silent while it stays unreadable: read `status.json` for the current state. 

Auditing all of this from outside, in one command and with the standard library only: `python3 scripts/audit_public.py` fetches the published files, checks the event-log chain, the signed manifest and its signature (pynacl), the schemas, the methodology registry, and re-reads a random sample of scores from the oracle contracts over public RPCs; `--watch watch` audits a local checkout, `--sample N` sets the sample, `--ref <commit>` audits a past run as it was committed (its signed manifest, chain and schemas), since every run commits its manifest. Exit 0 means every check passed.

Each share page's JSON also carries `consumer_example` (what src/ExampleConsumer.sol answers today for the target: revert when stale, collateral factor 0 under 60, 50% to 80% above) and `cheapest_fix` (the smallest single-axis move that reaches the next band, from the published formula 40% admin + 30% multisig + 30% timelock).

Reproducing a read: every share page (`/oracle/p/<chain>-<address>.html` and its `.json` twin, field `reproduce`) carries the exact `eth_call` (oracle, calldata, block of the build) that re-reads the score from the public RPC; the 6th word of the answer is the composite. One RPC (Hyperliquid testnet) answers for the latest block whatever block is asked, measured on 2026-10-10 with the same `trackedTargetsCount()` at block 1 and at latest: those pages say so and pin `latest` (`block_honoured: false`).

What changed since a moment: the dashboard takes `#since=<UTC time>` (for instance `#chain=all&since=2026-10-10T06:00Z`) and lists every move and alarm of `events.jsonl` recorded after it; the button under the hero copies such a link marked at the current time.

Subscribing: every run commits to `watch/`, so a GitHub webhook on this repository (event `push`, filter on paths under `watch/`) tells your service within seconds; the Atom feeds (`feed.xml`, `alerts.xml`) and the calendar (`pending_ops.ics`) need no account; the dashboard's "notify me" polls `latest.json` every 10 minutes in the browser.

**Signed webhook for a machine.** If the workflow has the secrets `ALERT_WEBHOOK_URL` (https only) and `ALERT_WEBHOOK_SECRET`, every run that raises new alerts POSTs `{"event":"alerts","version":1,"sent_utc","alerts":[{rule,severity,chain,target,title,score,delta,tvl_usd,first_seen}],"page"}` (ten at most). Headers: `X-ARO-Timestamp` (unix seconds) and `X-ARO-Signature: sha256=<hex>`, the HMAC-SHA256 of `<timestamp>.<raw body>` with your secret. Check the signature on the raw bytes with a constant-time comparison and refuse a timestamp more than five minutes old. This repository is public: the secret and the URL are the owner's, set in the repository settings, never committed.

Signer addresses: every root-signer address is shortened (except a tracked contract that also signs elsewhere) (`0x1234…abcd`) in these files by `scripts/redact_signers.py`; the index of who can reach what is never published.
